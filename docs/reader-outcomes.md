# Reader outcomes and contextual CTAs

This is a measurement plan, not a claim of conversion improvement. No private funnel or activation data was available in this review. The existing placements stay in place; a signup click alone does not establish that a reader learned something or successfully used a database.

The public browser check found the legacy Universal Analytics proxy request blocked by production CSP. This branch removes that retired integration and uses the already configured PostHog pageview and explicit CTA transport. Google [ended Universal Analytics](https://support.google.com/analytics/answer/10089681?hl=en); widening CSP to revive that request would not validate the outcome funnel. Destination activation observations remain unverified.

| Question                                     | Evidence needed                                                                                  | Boundary                                                                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Did the lesson answer the reader's question? | Optional, explicit helpfulness/task-completion feedback, grouped by article and content revision | Scrolling or copying is an interaction, not comprehension.                                                             |
| Could the reader complete the exercise?      | Opt-in exercise completion or a successful first query from the destination product              | Never collect query text, credentials, database rows or copied code.                                                   |
| Did a relevant CTA help the reader continue? | CTA click followed by consented, attributed signup, database creation and successful first query | Count the downstream outcome separately from the click; define an attribution window and deduplicate users/operations. |
| Did a placement harm reading?                | Dismissals, task feedback and accessibility checks, alongside the outcome rate                   | Avoid optimizing signup clicks at the expense of lesson completion.                                                    |

`dataguide_cta_click` carries article path, placement, cluster, destination path and content revision. It excludes destination query strings, search text and code. A single delegated listener handles links including the nested mobile CTA, and an injected-transport test proves dispatch and cleanup. PostHog sends the event only when the existing configured client has initialized; local credential-free checks send no analytics. The destination's existing UTM tags provide attribution inputs, but do not prove that a downstream event is already joined to this event.

Before drawing conclusions, the analytics and product owners should agree on consent, attribution, the qualified activation definition, eligibility and exclusions, and a reporting window. Events from `www.prisma.io` are labeled production, loopback hosts local and other hosts preview; filter by this environment before comparing outcomes. Confirm downstream database-created and successful-query events in the product's own instrumentation; this repository cannot manufacture those observations. Validate event deduplication and joins with synthetic accounts in an approved test environment.

Report the denominators, observed counts, observation dates, content revision, attribution window and uncertainty. Compare each article's learning outcome and qualified activation, not just its click-through rate. A controlled placement experiment needs a declared hypothesis and enough observations to support its decision. No uplift or statistical significance is asserted here.
