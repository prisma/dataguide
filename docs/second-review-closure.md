## Incremental publication and indexing follow-up

Search records now hash their complete published payload and the indexer's source instead of retaining the MDX node digest. The build's content hash and source commit go into one revision record rather than into every record, so a deploy no longer rewrites all of the index's records. The [successive-build test](../plugins/gatsby-algolia-indexer/incremental.test.mjs) runs the installed Algolia publisher with a fake network client and persistent cache: a new commit or content hash rewrites only the revision record, changed output rewrites the affected records, an indexer source change rewrites all of them, legacy digests are replaced, identical builds skip writes, and a removed article's records are deleted. This establishes the local synchronization decision, not a successful hosted index publication.

The Markdown exporter records ownership and prunes exports after removal, rename, `publish: false`, `skipBuild: true`, `export: false`, or exclusion. Its [incremental fixture](../plugins/gatsby-plugin-markdown-export/incremental.test.mjs) retains the cache throughout and preserves unrelated static Markdown. A one-time signature scan adopts old generated exports so the repair also removes files left by the previous exporter.

The PostgreSQL logging lesson now uses an unquoted parameter name and demonstrates both numeric milliseconds and a quoted time unit. The [new PostgreSQL run](../tests/tutorials/evidence/postgresql-publishing-followup-2026-10-01.json) records eleven successful groups and verified cleanup, including extracted logging statements, configuration reload, existing versus new connection defaults, and real slow-query log presence in the database with the lower threshold and absence at the global threshold. Historical statistics, timestamps and paths remain explicitly illustrative; the article retains its scoped notice and has no date bump.

Deployment checks now require explicit preview/production mode and the canonical site root. Their [HTTP fixtures](../plugins/gatsby-plugin-content-manifest/deployment.test.mjs) reject incorrect or missing HTML/Markdown/header canonicals, production meta/header `noindex`, and blocking or invalid production robots policies while content/source revisions still match and routes return HTTP 200. Preview fixtures allow `noindex` headers and require blocked crawling. The robots tests cover crawler-specific groups, merged groups, longest matching paths, Allow ties, wildcards and end anchors. All 68 unit tests pass on Node 22.18.0 and 24.18.0; the publishing fixtures also pass in a disposable pinned Node container. These local controls do not close the hosted preview, origin robots or live-index release requirements.
